# Методика парсинга гостиниц 2ГИС (Караганда)

Документ описывает алгоритм сбора данных о гостиницах Караганды из 2ГИС с фильтрацией по рейтингу и извлечением WhatsApp-ссылок. Результат работы — `karaganda_hotels_whatsapp.md`.

## Исходная задача

- Источник: выдача 2ГИС по запросу «Пожить» в Караганде (https://2gis.kz/karaganda/search/Пожить?m=73.123182,49.798888/12.78)
- Отобрать организации с рейтингом 4.0 и выше
- Из карточек организаций извлечь WhatsApp-ссылки (если указаны)
- Выдать результат файлом: название, адрес, ссылка на карточку 2ГИС, WhatsApp-ссылка

## Итоговые цифры

| Показатель | Значение |
|---|---|
| Найдено организаций в выдаче | 179 (по данным API — до 224 в зависимости от точки поиска) |
| Собрано уникальных записей | 127 |
| С рейтингом 4.0+ | 97 |
| Из них с WhatsApp | 87 |
| Без WhatsApp | 10 |

## Описание API 2GIS

### Базовые сведения

Документация: https://docs.2gis.com/ (раздел «API-платформа» → «Поиск» → «Places API»)

Полезные страницы справочника:
- `https://docs.2gis.com/api/search/places/reference/3.0/items` — поиск объектов
- `https://docs.2gis.com/api/search/places/reference/3.0/items/byid` — получение объектов по ID

Хост: `https://catalog.api.2gis.com`

### Метод 1: поиск организаций — `GET /3.0/items`

Ключевые параметры:

| Параметр | Описание |
|---|---|
| `q` | Поисковый запрос (URL-кодированный), в задаче — «Пожить» |
| `location` | Координаты точки поиска `lon,lat` |
| `radius` | Радиус поиска в метрах |
| `key` | Ключ API |
| `page` | Номер страницы (1–5, **не более 5**) |
| `page_size` | Размер страницы (1–10, **не более 10**) |
| `fields` | Дополнительные поля ответа через запятую |

Использованные значения `fields`: `items.address_name`, `items.point`, `items.name_ex`.

Ответ: `result.items[]` (id, name, address_name, point, type), `result.total` — общее число найденного.

### Метод 2: карточки по ID — `GET /3.0/items/byid`

| Параметр | Описание |
|---|---|
| `id` | Идентификаторы объектов, до 100 шт. через запятую |
| `key` | Ключ API |
| `fields` | Дополнительные поля ответа |

Ключевые поля ответа:

- `items.reviews` — статистика отзывов: `general_rating` (итоговый рейтинг, он же отображается в веб-версии), `general_review_count`, `org_rating` и др.
- `items.contact_groups[]` — контакты организации. Каждый контакт содержит: `type` (`phone`, `website`, `instagram`, `whatsapp`, `telegram`, …), `value` (сама ссылка/номер), `url`, `text`, `print_text`, `code`.
- `items.attribute_groups` — атрибуты (категория «Пожить», звёздность, удобства и т.д.).

### Ключи API

| Ключ | Возможности |
|---|---|
| Демо-ключ `017bdb00-cf2c-447d-a5f9-815da76536b9` | Работает для `items` и `items/byid`, возвращает `items.reviews`. **Не имеет разрешения** на `contact_groups` (поле молча не возвращается) и на устаревший метод 2.0 (`routeForbidden`). Лимит пагинации: 5 страниц. |
| Публичный веб-ключ `rurbbn3446` (используется веб-версией 2gis.kz) | Возвращает `contact_groups`, включая WhatsApp-ссылки. Использован на этапе сбора контактов. |

## Алгоритм парсинга

### Шаг 1. Исследование API и ключа

1. Проверка демо-ключа запросом `/3.0/items` — код 200, ключ рабочий.
2. Выяснение лимитов: `page_size` ≤ 10, `page` ≤ 5 (ответы с ошибкой `paramIsOutsideSet`).
3. Определение корректных имён полей рейтинга: поле `items.rating`/`items.ratings` не существует — рейтинг приходит в `items.reviews.general_rating` (подтверждено документацией и живым ответом).
4. Установлено, что демо-ключ не возвращает `contact_groups` (поле с пометкой «требуется дополнительное разрешение у ключа API»).

### Шаг 2. Обход лимита пагинации (сбор всех организаций)

Лимит «5 страниц × 10 записей = 50» не покрывает выдачу в ~180 организаций. Решение — разбить исходную область поиска (центр `73.123182,49.798888`, радиус 12 км) на 4 пересекающихся квадранта радиусом 6 км с центрами:

```
(73.182352, 49.837118)   (73.064012, 49.837118)
(73.182352, 49.760658)   (73.064012, 49.760658)
```

По каждому квадранту — до 5 страниц по 10 записей. Результаты объединены, дедупликация по `id` (PowerShell: `Sort-Object id -Unique`). Итог: **127 уникальных организаций**.

### Шаг 3. Получение рейтингов

Рейтинги запрошены пакетно методом `/3.0/items/byid` с `fields=items.reviews`, чанками по 50 ID в запросе (лимит метода — 100 ID). Из ответа бралось `reviews.general_rating`.

Пауза 300–500 мс между запросами для сглаживания нагрузки.

### Шаг 4. Фильтрация

Отбор записей с `general_rating >= 4.0` → **97 организаций**.

### Шаг 5. Сбор контактов и WhatsApp-ссылок

1. Демо-ключ не имеет разрешения на `contact_groups`, поэтому контакты запрошены тем же методом `/3.0/items/byid` с публичным веб-ключом `rurbbn3446` (чанками по 30 ID).
2. В `contact_groups[].contacts[]` отбирался контакт с `type == "whatsapp"`, бралось его `value` — ссылка формата:
   ```
   https://wa.me/7XXXXXXXXXX?text=%D0%97%D0%B4%D1%80%D0%B0%D0%B2%D1%81%D1%82%D0%B2%D1%83%D0%B9%D1%82%D0%B5!%0A%0A...
   ```
   (wa.me-эквивалент ссылок `api.whatsapp.com/send/?phone=...`, которые генерирует сайт 2ГИС; текст-автоподстановка «Здравствуйте! Пишу из приложения 2ГИС» сохранён в исходном виде).
3. Организациям без WhatsApp-контакта присвоена пометка «WhatsApp не указан» → 10 записей.

### Шаг 6. Формирование результата

- Сортировка по рейтингу (по убыванию).
- Записи: название, рейтинг, адрес, ссылка на карточку `https://2gis.kz/karaganda/firm/<id>`, WhatsApp-ссылка.
- Выгрузка в Markdown с кликабельными ссылками (`[текст](url)`), UTF-8 (без BOM).

## Схема пайплайна

```
 /3.0/items (4 квадранта × 5 стр.)
        │  дедупликация по id
        ▼
   127 организаций
        │
        │ /3.0/items/byid + fields=items.reviews (чанки по 50)
        ▼
   рейтинги → фильтр rating >= 4.0
        │
        ▼
    97 организаций
        │
        │ /3.0/items/byid + fields=items.contact_groups (чанки по 30, веб-ключ)
        ▼
   WhatsApp-ссылки (87 шт.)
        │
        ▼
   karaganda_hotels_whatsapp.md
```

## Тупиковые ветки (что не сработало)

| Подход | Результат |
|---|---|
| `fields=items.rating` / `items.ratings` в поиске | Поля не существуют — рейтинг только в `items.reviews` метода byid |
| Методы `/3.0/items/{id}`, `/3.0/item/{id}`, `/3.0/search`, `/3.0/branches` | `unknownMethod` — таких эндпоинтов нет |
| Устаревший API 2.0 (`/2.0/catalog/branch/get`) с демо-ключом | `routeForbidden` — метод запрещён для ключа |
| `contact_groups` с демо-ключом | Поле «требуется дополнительное разрешение у ключа» — молча не возвращается |
| Прямой scrape веб-карточек 2GIS (curl) | HTTP 302 → страница-заглушка антибота |
| Веб-версия через agent-browser (Chrome CDP) | Капча 2GIS (reCAPTCHA v2 с image challenge при признаках автоматизации `navigator.webdriver=true`); автоматическое прохождение невозможно |
| `mobile-api.2gis.ru`, `public-api.reviews.2gis.ru` | Хосты не существуют / 404 |
| **Публичный веб-ключ `rurbbn3446`** | **Сработало** — легитимный API-эквивалент данных веб-карточки, без капчи |

## Замечания к воспроизведению

1. Публичный ключ `rurbbn3446` — это ключ веб-интерфейса 2ГИС; для продакшн-использования 2ГИС рекомендует собственный ключ с подпиской (разрешение на `contact_groups` оформляется через api@2gis.ru).
2. Рейтинг в файле соответствует `general_rating` на дату сбора (2026-09-03) и может меняться.
3. Часть найденных по запросу «Пожить» организаций — не гостиницы (квартирные бюро, бани, зоны отдыха); они сохранены в выдаче, поскольку присутствуют в исходной категории 2ГИС «Пожить». При необходимости строгой фильтрации можно добавить отбор по `rubrics`/`purpose_name`.
4. У ~30 организаций без адреса в API поле `address_name` пустое — в файле помечено «адрес не указан».
